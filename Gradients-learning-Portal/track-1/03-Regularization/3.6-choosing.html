How to Choose the Right Regularization

Here is a simple decision framework:

  • Use Lasso (L1) when you suspect only a few features are truly relevant and you want automatic feature selection.
  • Use Ridge (L2) when all features contribute meaningfully and you want smooth shrinkage without sparsity.
  • Use Elastic Net when features are correlated and you need both sparsity and stability.
  • Tune $\lambda$ (or $C$) using cross-validation â€” start with a logarithmic range (e.g., $C \in [0.001, 0.01, 0.1, 1, 10, 100]$) and monitor validation accuracy.
⚠️
Effect of Increasing Lambda: As regularization strength $\lambda$ increases, model weights are pushed closer to zero, decreasing variance but increasing bias. If $\lambda$ is too large, the model underfits (all weights near zero).

Lesson 3.5: Scaling & Pipeline Pitfalls

Why Feature Scaling is Mandatory: Because the regularization penalty sums the magnitudes of the weights, features must be scaled to the same range (e.g., using StandardScaler). If one feature has values in the thousands and another between 0 and 1, the model will need a larger weight for the second feature to use it, which gets penalized unfairly.

Regularization Strength in Scikit-Learn:

In many Scikit-learn models (like `LogisticRegression`), the regularization hyperparameter is parameterized as `C`, the inverse of regularization strength:

C \propto \frac{1}{\lambda}
  • Small `C` (e.g., 0.01): Strong regularization (large penalty). Weights are pushed hard toward zero.
  • Large `C` (e.g., 100): Weak regularization (small penalty). The model is free to fit the training data closely.
